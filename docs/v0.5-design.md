# v0.5 设计（final）：可信单任务回归

状态：final，已按评审修正  
目标版本：0.5.0（alpha.1 / alpha.2 / 0.5.0）  
前置版本：0.4.0（录制 / 重放 / 矩阵 / 断言 / CI CLI）

## v1 → v2 修订

| 修订 | 原因 |
|---|---|
| preset 并入变体键 | 同一单元格混不同 preset 会让通过率失真；现在改最便宜 |
| 夹具生命周期补全：只对空闲会话快照、删除 run 联动删夹具、安全清理 | 避免撕裂快照、磁盘泄漏、删了仍被引用的夹具 |
| 批量要求 `fixture.status = ready` | 否则批次内现场漂移，重复运行测的是噪声 |
| CI 可移植性：`--workspace` 覆盖 + 明确文件断言的本地依赖 | CLI 换机器后 `file-*` 不能静默失败 |
| 砍 `taskFamily`、`final-json-schema`、重启恢复 | 空字段 / 维护成本 / 罕见恢复场景，留到 v0.6 |
| 缓存移到阶段 B | 没有夹具时缓存文件断言不安全，收益也小 |
| 工期 7–8 周 | v1 的 6 周把批量 + 恢复 + 统计压得太紧 |
| 审批计数先验证 `never` 下是否落盘 | 不确认就做 `max-approval-requests` 可能是空断言 |

## 1. 目标

把矩阵从手工报表变成可重复、可解释、可门禁的实验：

1. **效度**：断言检查真实行为（工具调用、文件变化、沙箱/审批），不只看最终文本。
2. **可复现**：重放基于录制时刻的工作区快照，而不是重放时刻的现场。
3. **可规模**：一个任务 × 多个变体 × N 次重复，有预算、可取消。

## 2. 非目标（v0.5）

- 不做通用评测平台：不做数据集管理、PR 评论、趋势仪表盘、成本看板。
- 不做 Task 实体迁移：任务身份仍是提示词哈希；不引入 `taskFamily`。
- 不做确定性 LLM 回放（ReplayEnvelope）。
- 不做定时实验、CI 侧产生运行（`agent-lab run`）。
- 不做批量重启恢复：job 持久化只用于观测与取消，重启后标记 `interrupted`。
- 不做多任务并发：全局同一时刻只允许一个重放或批量。

## 3. 分期与验收（7–8 周）

### 阶段 A（2 周）：深断言 + 预览 + 变体键修正

新增 8 类断言（`changed-files` 在 B）：

| 断言 | 参数 | 语义 |
|---|---|---|
| `tool-called` | `name` | 至少一次调用该工具 |
| `tool-not-called` | `name` | 完全没有调用该工具 |
| `tool-args-contains` | `name`, `text`, `key?` | 至少一次该工具调用，参数序列化后包含 `text`；给了 `key` 只看该参数 |
| `sandbox-mode-is` | `mode` | 运行的 `sandboxMode` 等于指定值 |
| `approval-policy-is` | `policy` | 运行的 `approvalPolicy` 等于指定值 |
| `file-exists` | `path` | 工作区存在该文件 |
| `file-not-exists` | `path` | 工作区不存在该文件 |
| `final-regex` | `pattern`, `flags?` | 最终回复匹配正则；flags 仅允许 `i`/`m`/`s` |

- **变体键修正**：`provider/model@effort#preset`；preset 缺省为 `default`。旧 run 读取时自动重键，无需迁移；CLI 的 `--variant` 与矩阵列随之变化。
- 断言编辑器新增「用已知坏 run 预览」：`POST /api/checks/preview` 只求值，不保存、不缓存。
- 预览的 run 列表来自当前 task 的矩阵数据，不新增查询接口。
- `final-regex` 在保存时编译校验，非法 pattern/flags 直接 400；`flags` 不允许 `g`。
- 审批计数（`max-approval-requests`）推迟到验证 `never` 策略下 `approval/asked` 是否落盘之后。

验收：

1. 调用禁用工具体的 run 被 `tool-not-called` 判 FAIL，CLI 退出 1。
2. `sandbox-mode-is: workspace-write` 对重放运行通过，对 `danger-full-access` 的导入运行失败。
3. 预览用一条已知坏 run 能看到失败项，且不改变已保存断言。
4. preset 不同的 run 在矩阵中是不同列，不再混算。
5. 旧 6 类断言与既有 29 个测试不回退。

### 阶段 B（3 周）：固定夹具 + 环境指纹 + 文件变化断言 + 缓存

- **录制即快照**：`POST /api/capture` 保存 run 后异步创建夹具，`run.fixture.status` 为 `preparing → ready | deferred | failed | too-large`。
- **只对空闲会话快照**：会话存在未闭合 turn（最后一个 `turn/start` 晚于最后一个 `turn/end`）时，夹具状态为 `deferred`，不复制；用户可在会话结束后点「再次固定」触发 `POST /api/fixtures/retry`。
- **夹具目录**：`fixtures/<fixtureId>/{fixture.json, manifest.json, workspace/}`；`workspace` 是完整快照（含 `.git`、`node_modules`、未跟踪文件），`manifest` 默认排除 `.git`。
- **重放从夹具复制**：`preserveTimestamps: true`；不再读现场。
- **环境指纹**：`env = { profile, platform, node, bundles, dshVersion }`；`bundles` 来自 `profileContext.startedBundles`，缺失字段为 null。
- **文件变化断言**：`changed-files`，参数 `allow`、`exclude`（默认 `['.git']`）；与 manifest 比较 size/mtime，可疑文件再比内容 hash。
- **缓存**：`check-results/<runId>.json`，键为 `checksHash + fixtureId`；只对 `ready` 夹具缓存；`preparing`/`deferred`/`failed`/`too-large` 不写缓存。
- **删除联动**：删除 run 时，删除其夹具与缓存（当夹具不再被其他 run 引用）。
- **安全清理**：`POST /api/fixtures/cleanup` 只删除无 run 引用的夹具目录；默认 dry-run，`apply: true` 才删。

验收：

1. 仓库前进一个 commit 后，旧 run 重放仍看到录制时文件内容（用 `file-contains` 验证）。
2. 运行创建 `out/extra.txt` 时，`changed-files allow: ['src/']` 失败；只改 `src/` 时通过。
3. 非 git 目录能固定并重放；超过 2 GiB / 20 万文件时状态 `too-large`，重放明确拒绝。
4. 在会话运行中捕获，夹具为 `deferred`；turn 结束后 retry 变 `ready`。
5. 删除 run 后夹具与缓存不残留；cleanup 不会删仍被引用的夹具。

### 阶段 C（3 周）：批量 × 重复 × 预算 + JUnit + 矩阵统计

- **批量实验**：`POST /api/batch`，base run、变体数组、`repeats`（1–3）、预算；顺序执行，逐项落盘。
- **前置条件**：base run 的 `fixture.status` 必须为 `ready`；否则 409，并提示先固定工作区。
- 批量固定使用 base run 的提示词；不支持逐项改提示词。
- **预算**：`maxTokens`（input+output）与 `maxDurationMs`；每项开始前检查，运行中轮询超限即取消当前轮。预算是软上限，单步可能小幅越界；cache-read Token 单独展示、不计入。
- **持久化**：`jobs/<jobId>.json`，每项结束原子写；重启后 `running → interrupted`，**不提供恢复**，只保留证据与取消。
- **矩阵统计**：单元格显示 `n`、通过率与 95% Wilson 区间；`n<3` 标注「样本少」。
- **JUnit**：CLI `--junit <path>`，每个断言一个 testcase，失败带 message；退出码不变。

验收：

1. 1 任务 × 2 变体 × 3 次在预算内完成；矩阵每格 `n=3`，显示通过率与区间。
2. 预算极小值时在超限处停止，状态 `budget-exceeded`，已完成 run 保留。
3. 批量进行中重启：job 变 `interrupted`，不假装完成。
4. `--junit out.xml` 可被 CI 解析，断言失败退出 1。

## 4. 数据模型

### 4.1 Run（schemaVersion 3，纯增量）

```json
{
  "schemaVersion": 3,
  "fixture": {
    "id": "fixture-m3x9-a1b2",
    "status": "ready",
    "kind": "snapshot",
    "sourceCwd": "D:\\work\\repo",
    "dir": "C:\\...\\agent-lab\\fixtures\\fixture-m3x9-a1b2\\workspace",
    "sizeBytes": 12345678,
    "fileCount": 4321,
    "git": { "commit": "abc1234", "branch": "main", "dirty": true },
    "capturedAt": 1793700000000
  },
  "env": { "profile": "desktop", "platform": "win32", "node": "v24.21.0", "bundles": [], "dshVersion": null },
  "batch": { "jobId": "batch-...", "variantKey": "p/m@high#standard", "repeat": 1 }
}
```

- 旧 run 缺字段按 `fixture: null`、`env: null`。
- `fixture.status`：`preparing | ready | deferred | failed | too-large | none`。
- `deferred` 不是失败：等待会话 idle 后 retry。

### 4.2 变体键（v2）

```
variantKey = `${provider}/${model}@${effort ?? 'default'}#${preset ?? 'default'}`
```

- 例：`deepseek-account/deepseek-flash@high#cordis`。
- 键在读取时计算，不落盘，因此无需迁移；旧数据自动按新键分组。
- 矩阵列头显示 model、provider、effort、preset；label 由 `variantOf` 统一生成。

### 4.3 Checks

- 存储文件格式不变（仍是 `{ taskKey, checks, updatedAt }`）；新类型是增量。
- 新类型在 v0.4 读取器中会显示 `unknown check type` 并失败，不回退成通过。
- `final-regex` 的 `pattern` ≤ 2000 字符，保存时编译；`flags` 只接受 `ims` 的子集。

### 4.4 Fixture

```
fixtures/<fixtureId>/
  fixture.json      # 来源、大小、文件数、git 元数据、limits、warnings
  manifest.json     # { "src/a.ts": { size, mtimeMs } }，排除 .git
  workspace/        # 完整快照（含 .git、node_modules、未跟踪文件）
```

- 上限：2 GiB / 200000 文件；超限 `too-large`，不复制。
- `fs.cp(..., { recursive: true, preserveTimestamps: true })`；符号链接尽量保留，失败回退 dereference 并写 warning。
- 不自动删除；删除 run 联动；cleanup 只删孤儿。

### 4.5 Job

```json
{
  "id": "batch-...",
  "kind": "batch",
  "status": "running",
  "spec": { "baseRunId": "run-...", "variants": [], "repeats": 3, "budget": { "maxTokens": 500000, "maxDurationMs": 3600000 } },
  "items": [{ "index": 0, "variantKey": "p/m@high#standard", "repeat": 1, "status": "completed", "runId": "run-..." }],
  "usedTokens": 12345,
  "startedAt": 1793700000000,
  "updatedAt": 1793700000000,
  "error": null
}
```

状态：`queued → running → completed | budget-exceeded | cancelled | interrupted`。  
item：`pending | running | completed | failed | cancelled | budget-cancelled | abandoned`。

- 单项失败不终止 job；预算/取消/重启才终止。
- 重启时正在跑的 item 标记 `abandoned`，不自动捕获。
- 不提供 resume；`interrupted` 是终态，保留已完成项。

## 5. API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/checks/preview` | `{ runId, checks }`，只求值 |
| GET | `/api/matrix` | 增加 `n`、`interval`、`fixture`、`preset`；默认读缓存 |
| GET | `/api/matrix?fresh=1` | 绕过缓存 |
| POST | `/api/fixtures/retry` | 重新固定（`deferred`/`failed`/`too-large` 可重试） |
| POST | `/api/fixtures/cleanup` | 清理孤儿夹具；默认 dry-run |
| POST | `/api/batch` | 创建批量 |
| GET | `/api/batch?id=` | 查询 |
| GET | `/api/batch/latest` | 当前/最近 |
| POST | `/api/batch/cancel` | 取消 |

单次重放沿用 `/api/replay`；与批量共享单活跃锁。

## 6. UI

- **矩阵**：单元格 `67%`、`2/3 · n=3`、均值；`n<3` 标「样本少」；tooltip 显示区间；任务行显示夹具状态徽标；列头显示 preset。
- **批量**：选变体、重复（1–3）、预算；开始前粗估 Token；进行中显示已完成/总数、当前变体、已用 Token；完成后刷新矩阵。
- **断言编辑器**：8 类新字段；「用已知坏 run 预览」选择该任务的 run，展示当前编辑中的断言结果，不保存。
- **单元格详情**：夹具来源（commit/快照）、环境、batch 溯源；preset 不同在这里分开展示。
- **未固定/待固定**：重放按钮禁用并提示；提供「固定工作区」入口。

## 7. CLI 与 CI 可移植性

- 新断言自动生效；`--junit <path>` 输出每个断言一个 testcase。
- 新增 `--workspace <dir>`：覆盖 run 的 workspace，供 `file-*` 断言使用。
- 契约：`file-*`/`changed-files` 需要本机存在 workspace 或夹具；只拷 run JSON 到 CI 时，请使用非文件断言，或显式传 `--workspace`。
- CLI 永远重算，不读缓存，保证与矩阵口径一致。

## 8. 缓存

- `check-results/<runId>.json`：`{ checksHash, fixtureId, passed, results, evaluatedAt }`。
- 只在 `fixture.status === 'ready'` 时读写；其他状态不缓存。
- 矩阵命中条件：`checksHash` 与 `fixtureId` 都一致。
- 外部手改重放工作区不会使缓存失效；矩阵提供 `fresh=1` / 「重新评估」，CLI 重算。
- 删除 run 时删除对应缓存。

## 9. 兼容与迁移

- run 2 → 3 纯增量；v0.4 读取器忽略新字段。
- 变体键变化是**行为变化**：矩阵列、CLI `--variant`、批量 spec 都使用新格式；旧 run 自动重键，无数据迁移。
- 任务键不变；checks 文件格式不变。
- v0.5 不引入 `taskFamily`，也不做 JSON Schema。

## 10. 测试计划

纯逻辑：

- 8 类新断言：通过/失败/边界；`final-regex` 非法 pattern/flags；`tool-args-contains` 的 key/text 组合。
- `changed-files`：新增/修改/删除、allow/exclude、mtime 假阳性、缺失夹具。
- 夹具 manifest、diff、大小上限（临时目录真实 fs）。
- 变体键：preset 缺省、不同 preset 分列、CLI 选择。
- Wilson：n=0/1/3/10、0%/100%。
- 批量状态机与预算：顺序、单项失败继续、预算停止、取消、`interrupted`。
- JUnit XML 转义与结构。

集成：

- capture → `deferred` → retry ready → replay 从夹具复制。
- 批量 1×2×2（注入 fake executor，不打真实模型）。
- 缓存命中/失效/删除联动。

真实冒烟（少量调用）：一个任务、2 变体 × 2 次、预算内完成；破坏性 run 被断言挡住；JUnit 可解析。

## 11. 风险与开放问题

| 风险 | 缓解 |
|---|---|
| 夹具磁盘增长（含 `.git`/`node_modules`） | 2 GiB / 20 万上限；删除联动；cleanup |
| 撕裂快照 | 只对 idle 会话快照；`deferred` + retry |
| 非 git / 符号链接 / 权限 | 快照不依赖 git；链接失败回退并 warning |
| 批量成本失控 | 粗估 + 硬预算 + 运行中取消；默认 repeats=1 |
| 预算粒度 | 承认软上限；cache-read 单独展示 |
| 缓存读到过期文件 | 只对 ready 夹具缓存；`fresh=1`；CLI 重算 |
| CLI 换机器文件断言失败 | `--workspace` + 文档契约 |
| 审批计数不可得 | 先验证 `never` 审计；不可得就不做 |

开放问题：

1. 夹具清理是否要自动保留最近 N 个？v0.5 只做孤儿清理。
2. 单项失败是否重试？v0.5 不重试。
3. 金额预算：v0.5 只做 Token/时长，价目表留到后续。
4. 单次重放是否也持久化？v0.5 不做。
